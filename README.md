# candy-bouquet-bot

Телеграм-бот для продажи букетов из конфет. Внутри бота человек собирает букет сам: выбирает основу, конфеты и их количество, видит состав и цену, оформляет заказ.

Букеты собираю и продаю вручную. Бот автоматизирует то, что делалось в переписке: подбор состава, расчёт цены, учёт заказов.

## Модель данных

Четыре сущности: **основа**, **конфета**, **букет** и **заказ**.

```
Основа ──┐
         ├──> Букет ──> Заказ
Конфета ─┘
```

### Основа (`bases`)

Корзина или коробка, в которую втыкаются конфеты. Задаёт оба ограничения букета.

| Поле | Тип | Описание |
|---|---|---|
| `id` | int | |
| `name` | text | «Корзина S» |
| `slots_total` | int | сколько конфет физически помещается |
| `max_weight_g` | int | сколько граммов основа держит, не заваливаясь |
| `price` | int | цена основы, ₽ |

### Конфета (`candies`)

Позиция каталога: Ferrero Rocher, Raffaello и всё остальное, что идёт в букеты. Одна строка один вид конфет.

| Поле | Тип | Описание |
|---|---|---|
| `id` | int | |
| `name` | text | «Ferrero Rocher», «Raffaello» |
| `weight_g` | int | вес одной штуки |
| `price` | int | цена одной штуки, ₽ |
| `stock_qty` | int | сколько есть на руках |

### Букет (`bouquets` + `bouquet_items`)

Состав, собранный пользователем. Существует отдельно от заказа: букет можно собрать и не заказать.

`bouquets` — одна основа и автор состава:

| Поле | Тип |
|---|---|
| `id` | int |
| `base_id` | int → `bases` |
| `user_id` | int, Telegram id |

`bouquet_items` — строки состава, по одной на вид конфет:

| Поле | Тип |
|---|---|
| `bouquet_id` | int → `bouquets` |
| `candy_id` | int → `candies` |
| `qty` | int, больше нуля |

Одна конфета не может встретиться в составе двумя строками пара (`bouquet_id`, `candy_id`) уникальна.

Что считается по составу, а не хранится:

```
всего конфет = Σ qty
общий вес    = Σ qty × candy.weight_g
цена         = base.price + Σ qty × candy.price
```

### Заказ (`orders`)

| Поле | Тип | Описание |
|---|---|---|
| `id` | int | |
| `bouquet_id` | int → `bouquets` | |
| `user_id` | int | Telegram id покупателя |
| `status` | text | см. ниже |
| `price` | int | цена на момент оформления, ₽ |
| `contact` | text | телефон или @username |
| `created_at` | datetime | |

Цена копируется в заказ, а не считается заново. Цены в каталоге меняются, а покупатель платит ту сумму, которую видел.

## Статусы заказа

| Статус | Что значит | Куда дальше |
|---|---|---|
| `new` | заказ оформлен, ждём оплату | `paid`, `cancelled` |
| `paid` | оплата получена | `assembling` |
| `assembling` | букет собирается | `done` |
| `done` | передан покупателю | — |
| `cancelled` | отменён | — |

## Ограничения конструктора

Проверяются при каждом изменении состава, до показа цены. Пока хоть одно нарушено, кнопка «Оформить» не работает.

| № | Правило | Почему |
|---|---|---|
| 1 | всего конфет ≤ `base.slots_total` | больше просто не воткнуть |
| 2 | общий вес ≤ `base.max_weight_g` | перегруженная основа заваливается |
| 3 | `qty` ≤ `candy.stock_qty` | нельзя продать то, чего нет |

Букет из тысячи конфет собрать нельзя, и это не отдельная проверка, а следствие правила 1. Сколько бы пользователь ни ввёл, состав упирается во вместимость основы: в «Корзину S» на 15 мест шестнадцатая конфета не пройдёт. Самая большая основа в каталоге задаёт общий потолок.

### Пример

Основа «Корзина S»: 15 мест, 400 г, 450 ₽.

| Позиция | Шт. | Вес | Сумма |
|---|---|---|---|
| Ferrero Rocher (12 г, 65 ₽) | 9 | 108 г | 585 ₽ |
| Raffaello (10 г, 45 ₽) | 6 | 60 г | 270 ₽ |
| **Итого** | **15 / 15** | **168 / 400 г** | 855 ₽ |

С основой — **1305 ₽**. Места заняты полностью, по весу ещё большой запас. Добавить шестнадцатую конфету нельзя, так как сработает правило 1.
